# Evaluation: LLM-generated test failure-mode analysis

Every test generated by `specgen` is run and reviewed line by line, then each
finding is classified below. Counts, before/after snippets, and root-cause
notes are filled in **during human review** — this file intentionally ships
with the taxonomy only.

| Category | Definition | Count | Example / snippet | Root cause |
|---|---|---|---|---|
| **Correct & valuable** | Test is right and you'd keep it | | | |
| **Correct but shallow** | Passes, but asserts too little to catch real regressions | | | |
| **Plausible but wrong** | Looks professional, fails or tests the wrong thing | | | |
| **Hallucinated surface** | Tests endpoints/params/fields that don't exist in the spec | | | |
| **Dangerous if trusted** | Would pass while masking a real defect | | | |
| **Missing entirely** | Coverage a human SDET would demand that the LLM never generated | | | |

## Review protocol

For each category: count occurrences, include 1–2 concrete code snippets
(before/after correction), and a one-line root-cause note. Tests that survive
review are promoted — corrected — to `tests/curated/`.
